# 第三幕 · 从等价类到 θ：数字标签诞生

> 幕级切片：可单独投喂给一个新会话实现本幕。代码风格与文件结构基准见 `docs/scenes/scene1.md`。

## 目标

θ 真正"诞生"的一幕。学生必须经历：**分类 → 发现类别 → 想给类别编号 → 数字标签出现 → θ 出现**。

**禁止**直接给出 θ 的公式或数值；禁止"页面加载即出现 θ = 20"。θ 必须是从前面的逻辑里"长出来"的。

## 台词与画面（照抄，不要改写措辞）

- 画面：八个系统状态 A B C D E F G H，**开始时不要分组**
- 学生通过热平衡关系进行比较：`A ∼ B`、`A ∼ D` → A、B、D 自动聚成一组 → `[A] = {A, B, D}`
- 另一组：`[C] = {C, E, F}`；第三组：`[G] = {G, H}`
- 最终形成三个热平衡等价类；页面只留下 `[A]`、`[C]`、`[G]`
- 文字：热平衡关系把系统状态分成了若干个互不重叠的类别。
- 每一个类别，就是一个热平衡等价类。
- 文字：我们已经能够按热平衡关系分类。（停顿）
- 追问：**如果希望用一个数字标记每一个类别呢？**
- 按钮：给它们一个标签（**用户点击后，数字才出现**）
- `[A] → 20`、`[C] → 50`、`[G] → 80`
- 重新表示：`[A] → θ = 20`、`[C] → θ = 50`、`[G] → θ = 80`（**整个网页第一次出现 θ**）
- 展开 `[A] = {A, B, D}`，依次高亮 A、B、D
- `θ(A) = 20`、`θ(B) = 20`、`θ(D) = 20`
- 强调：**不同的系统状态可以拥有相同的 θ。**
- 因为它们属于同一个热平衡等价类。
- 核心关系（方框）：`A ∼ B  ⟺  θ(A) = θ(B)`
- θ 是对热平衡等价类的一种数值表示。
- 这样的 θ 可以作为一种"经验温度"。
- θ 不是系统状态与实数之间的一一对应。
- 正确的一一对应（方框）：`热平衡等价类  ⟷  温度数值标签`
- 留下问题：20 / 50 / 80 → 为什么是 20、50、80？ → 为什么不是 2、5、8？ → 为什么不是 40、100、160？
- **温度有了，但具体的"刻度"还没有。**
- 按钮：研究温度的刻度 →

## 交互

- "给它们一个标签"是**闸门**：必须由用户点击，点击前屏幕上不出现任何数字；与第二幕不同，这里**不做超时自动继续**。
- 类别是**逐类聚合**的：先是 A、B、D（能看到 D 从右上角走过去），再是 C、E、F，最后是 G、H——"分类"是热平衡关系的结果，而不是预先摆好的。
- 展开 `[A]` 时只有这一类的成员重新出现并依次高亮，用来说明"同一个等价类中的状态共享同一个 θ"。
- 重播后必须回到"未分组、无数字、无 θ"的初始状态（成员回到散落位置）。
- 窗口尺寸变化时按当前状态重排（散落 / 已聚合都要保持正确）。

## 本幕红线：不得出现

- 具体温标、摄氏、Kelvin、`T`
- θ 与系统状态一一对应的说法
- "第零定律推出了数字"这类表述；必须说明赋数字是**我们主动做出的数值表示选择**
- 任何把 20 / 50 / 80 说成"真实温度"的表述

## 物理精度要点

- 真正建立一一对应的是：**热平衡等价类集合 ⟷ 所选温度数值集合**。不同等价类不能共用同一个标签。
- 同一等价类内的多个状态共享同一个 θ：`θ(A) = θ(B) = θ(D)`。
- 给等价类赋数字不是等价关系数学性质的自动产物，而是一次**数值表示的选择**。
- 本幕不得给出"尺度"从何而来的答案（留给第四、五、六幕）。
