# 第七幕 · 现在，我们真的可以测温了

> 幕级切片：可单独投喂给一个新会话实现本幕。代码风格与文件结构基准见 `docs/scenes/scene1.md`。

## 目标

最后一幕**不引入新理论**，让学生把整条逻辑链重新走一遍——像一个"概念回收实验"。

学生应能独立复述：`热平衡 → 第零定律 → 等价类 → θ → 具体温标`。

## 台词与画面（照抄，不要改写措辞）

- 出现三个系统：`A, B, C`，其中 A、B、C 可以进行热接触。
- 提问：哪些系统处于同一个热平衡类别？
- 交互：让学生点击或拖动系统完成分类。
  - 例：A 与 B 热平衡；B 与 C 热平衡。
  - 根据第零定律：`A ∼ B,  B ∼ C` ⟹ `A ∼ C`
  - 三个系统自动聚成一个等价类。
- 聚类后出现：`[A] = {A, B, C}`
- 然后让学生给这个等价类选择一个数字标签（例：50）→ `[A] → 50`
- 显示：`θ(A) = θ(B) = θ(C) = 50`
- 按钮：换一种温标 → 出现 `T = 323.15 K` 以及 `t = 50 °C`
- **谨慎说明（必须照做）**：
  - 如果之前使用的是任意经验标签 `θ = 50`，**不要直接声称 `θ = 50` 必然等于 `50 °C`**。
  - 应明确说明：这是一个新的、经过物理定义和标定建立起来的具体温标。
  - 如果选择 `t = 50 °C`，则对应 `T = 323.15 K`。
- 回到第一幕：页面逐渐回到 `温度相等 → 热平衡 → 温度相等`
- 然后这一次，学生已经知道：我们不能从这里开始。
- 画面把第一幕的闭环"拆开"，重新排列：

```text
热平衡现象
   ↓
热平衡关系
   ↓
第零定律
   ↓
等价关系
   ↓
等价类
   ↓
数值标签
   ↓
θ
   ↓
具体物理规律
   ↓
具体温标
```

- 最终屏幕只留下（方框）：`A ∼ B  ⟺  θ(A) = θ(B)`
- 温度首先是对热平衡等价类的一种数值表示。
- 第零定律让这种表示成为可能。
- 而具体的温标，则需要更多物理学来确定。

## 交互

- 分类用**点选**：点第一个系统选中（高亮），再点第二个即完成配对；键盘用户可用 Tab + Enter 完成同样操作。（按用户要求，界面上不再提示"拖动"；拖动配对的代码仍保留在 `scene7.js` 里，随时可以彻底移除。）
- 用户只需建立**两条**关系，第三条由**第零定律（传递性）**自动补上；若用户把三条都连出来了，第三条就不再标注为推导结果（不把用户的操作说成推导）。
- 数字标签可自定义（1–1000 的整数，默认 50）；"换一种温标"按钮在标签确定之后才出现。
- 闸门 2、3 都留了 **9 秒自动继续**的兜底；**闸门 1（分类）不设兜底**——必须由用户亲自建立关系，聚合才有意义。
- 重播后必须回到：三条关系全清空、标签回到 50、闭环恢复、两条链的延迟清空。
- 结束页之后**不再有"继续"入口**：本作品到此结束（只有署名与标志）。

## 本幕红线：不得出现

- 让任意经验标签与摄氏 / Kelvin 直接等同
- 暗示第零定律足以定出温标
- 新的理论内容（熵、统计物理、Carnot 推导等）
- 把第一幕的闭环当作正确推理再次使用

## 物理精度要点

- 第零定律在交互中的体现是**传递性**：`A ∼ B, B ∼ C ⇒ A ∼ C`。
- 数值标签的选择仍是**表示选择**；`θ = 50` 只是一个标签。
- 摄氏 50 °C ↔ 323.15 K 是**经过物理定义和标定**的具体温标之间的关系，与任意经验 θ 不是同一层级。
