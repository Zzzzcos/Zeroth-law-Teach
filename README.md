# 从热平衡到温度 · 交互式教学网页

面向大学基础物理学生的交互教材（不是知识介绍页，是一个"逻辑探究实验"）。核心问题：

> 假设我们还没有"温度"这个概念，仅从热平衡现象和热力学第零定律出发，
> 为什么可以用一个标量来表示冷热状态？

## 如何查看

**最简单：直接双击 `index.html`**（`file://` 下即可完整运行——本项目刻意不使用构建工具、ES module、fetch 本地文件，也没有任何 CDN 依赖）。

第一幕末尾的按钮进入 `scene2.html`，其后每一幕的按钮依次进入下一幕（`scene3.html` → `scene4.html` → `scene5.html` → `scene6.html` → `scene7.html`）；每一幕底部都有「← 上一幕」可以返回，每一幕的 HTML 也都可以单独打开。



键盘：`R` 重播本幕 · `Enter` 继续 · `Tab` 遍历可交互元素。

## 各幕怎么运作（第二幕 ~ 第七幕）

**第二幕**

- 热接触是**闸门**：必须点击"允许热接触"（若一直不点，7 秒后自动开始），动画结束后时间线才继续。
- 曲线不是贴图：脚本按"热流量先升后降"的形状逐点生成路径，再用 `stroke-dashoffset` 描边；两条曲线最后**并回零线、合成一条**，曲线与零线之间的**阴影面积 = 交换的总热量（不为 0）**。
- 中间那一格先是"允许热接触"，随后变成**系统 C**，于是自然形成 A —— C —— B。
- 三个性质先并列出现，再把"自反性 / 对称性 / 传递性"三个词向中央聚合，最后才给出方框结论。

**第三幕**

- 状态场用绝对定位 + 脚本计算坐标：8 个状态先散落，再**逐个类别移动**（先是 A、B、D 聚成一列，然后 C、E、F，最后 G、H）。
- "给它们一个标签"是**第二个闸门**，而且刻意**不做超时自动继续**：不点击，屏幕上永远不会出现数字。
- 数字先以 `→ 20 / 50 / 80` 落到类别上，再改写成 `→ θ = 20 / 50 / 80`——这是整个网页第一次出现 θ。
- 展开 `[A]` 只让这一类的成员重新出现并依次高亮，用来说明"同一个等价类中的状态共享同一个 θ"。

**第四幕**

- 两个交互**可点可不点**：换标签（最多两次）与相撞滑块，**8 秒没人动就自动演示**，保证页面对纯观看的学生也能走完。
- 相撞实验放在一条**数轴**上：`[C]` 固定在 10，把 `[A]` 的滑块拖到 10，两个标记就叠在一起——"两个类别被压成了同一个数字"。
- 单调性用**切换按钮**比较 `θ′ = 2θ + 5`（顺序保持：45 < 105）与 `θ′ = −θ`（顺序反转：−20 > −50）。
- 最后的总结链是**逐行出现**的（脚本给每个子元素写入递增的 `animation-delay`）。

**第五幕**

- 状态指示器由 **requestAnimationFrame** 驱动（约 6 秒一个来回），屏幕上**不出现任何数字**，只给"冷 / 较冷 / 中等 / 较热 / 热"这样的定性词。
- θ 滑块拖动时同步显示 `θ′ = 2θ + 5`，并给出"与它最接近的类别"，让学生看到**数字在变、所属类别不变**。
- 三把抽象尺子（0–30 / 0–300 / −20–40）**点击可藏**，用来比较刻度疏密与零点位置；它们只是抽象刻度，**不是**摄氏 / 华氏 / 开尔文。

**第六幕**

- 测温装置点一下就换状态（冷 / 中 / 热），**P 随之改变，V 与 n 固定**；这一节刻意**不显示 T**，把 T 留给后面的热力学温标。
- 理想气体温标与热力学温标是**两条并列的路线**：前者靠 `PV = nRT`，后者靠第二定律 + 可逆热机；页面上明确写出 **Kelvin 不是从第零定律推出来的**。
- 摄氏 ↔ Kelvin 用一个滑块联动（`t = T − 273.15`），直观体现"**单位大小相同、零点不同**"——正好回扣第四幕的重新标度。

**第七幕**

- 三个系统用**点选配对**：点第一个选中（高亮），再点第二个即完成配对；键盘用户 Tab + Enter 同样可以完成。（界面提示只讲点选；拖动配对的代码仍保留在 `scene7.js` 里。）
- 用户只要建立**两条**关系，第三条就由**第零定律（传递性）**自动补上，并标注"由前面两条与第零定律得到"；如果用户把三条都连了，第三条就不再标注为推导结果（更诚实）。
- 数字标签由用户输入（1–1000，默认 50）；"换一种温标"按钮在这一步之后才出现。
- **防误读的关键一处在 `applyLabel()`**：换温标后的说明文字会随用户选的标签动态变化——若选 50，就明确写"两者数值相同只是巧合"；若选别的数，就写"两者之间没有换算关系"。
- 第一幕的闭环用**纯 CSS 画的环 + 箭头尖**；"拆开"时整块淡到 22%、环改成虚线（**不能整块消失**，否则小标题"第一幕的那个推理："会孤零零地没有内容），随后出现重排后的 9 行链。
- 结束页在概念地图之后**不再提问**：改为作者署名（作者：Zhou Yixuan / 本作品由 Deepseek 协同生成。/ 感谢您的观看。）与一条**余弦函数曲线**作为标志。

## 跨幕约定（第三幕起请沿用）

1. 颜色、字体、时长、间距一律取自 `styles/base.css` 的设计令牌（`--accent`、`--dur-1/2/3`、`--measure`…），保证七幕像同一本书。
2. 跨幕共用的版面片段（`.scene__lead`、`.scene__canvas`、`.scene__foot`、`.cta-row`、`.handoff`、`.scene__utils`、`.btn`、`.box-text`）**只定义在 `base.css`**；每一幕的 `sceneN.css` 只写自己特有的样式，不要再重复定义。
3. 需要"按顺序出现"的元素加 `class="step"` 与唯一 `data-step="id"`，由 JS 添加 `.is-in` 触发出现；`--step-scale` 由脚本按 `prefers-reduced-motion` 下调。
4. 重播必须瞬时复位：在根元素加 `.is-resetting` 的那一帧内移除所有 `.is-in`（否则会倒放动画）。
5. 数学排版使用 `base.css` 中的轻量方案：`<span class="m">` 作容器、`<i>A</i>` 表示变量、`<span class="op">∼</span>` 表示关系符号、`.m-box` 表示方框结论。**不引入 KaTeX / MathJax**：本项目公式很少，而"离线双击即可运行"这条底线更重要。
6. 一幕一个 HTML 页面（`index.html` → `scene2.html` → `scene3.html` …），幕末按钮直接链接到下一幕；若下一幕尚未实现，则改用 `.handoff` 交接卡片 + 按钮。
7. 每完成一幕：更新本文件的进度表。

## 物理底线（不可妥协，逐条自检）

1. 不得用"温度相等"定义热平衡。
2. 热平衡的完整定义（三条件缺一不可）：**允许进行热接触 + 经过足够长时间后宏观状态不再发生变化 + 两者之间没有净热量交换**。不得**只凭**"没有热量传递"判定热平衡（两个绝热隔离的系统也没有热量传递）；也不得只凭"宏观状态不再变化"判定（稳态热传导时状态不变、热量却一直在穿过）。
3. 不得说第零定律"直接证明了温度存在"；它给出的是热平衡关系的等价结构。
4. 不得说自反性 / 对称性 / 传递性"自动产生了一个数字"；给等价类赋数字是**数值表示的选择**。
5. θ 对应的是**热平衡等价类**，不是系统状态（同一等价类内多个状态共享同一个 θ）。
6. 真正的一一对应是"热平衡等价类集合 ↔ 所选温度数值集合"。
7. 单射 / 双射 / 严格递增必须区分；严格单调 ⇒ 单射，不蕴含双射。
8. 任意经验标签不得直接等同于摄氏温度或 Kelvin 温度；具体温标需要超出第零定律的额外物理规律与标度规定。
